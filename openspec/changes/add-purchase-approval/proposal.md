# Пропозиція: другий зріз WS7 — подання закупівлі з урахуванням прав, рішення схвалювача, англійський інтерфейс

## Why

Форма заявки була заглушкою, і кожен розробник вирішував сам, кому які відділи й типи закупівлі показувати. Після цього
зрізу працівник у формі бачить лише свої відділи й дозволені типи закупівлі, подає закупівлю, і вона чекає рішення
схвалювача, а чужі відділи, заборонені типи й гість отримують відмову без змін у даних. Схвалювач вирішує лише по
заявках свого відділу: чужий відділ, власна заявка й заявник без права рішення отримують відмову, а заявка не
змінюється. Інтерфейсом користуються й англомовні колеги, тож усі тексти на екрані — англійською; логіка, ролі, статуси
й права не змінюються.

## What Changes

Подання закупівлі (`purchase-form`):

- У формі закупівлі працівник бачить лише відділи, де він заявник, і лише дозволені типи закупівлі; без відділів —
  повідомлення замість полів (AC-FRM-01, AC-FRM-03, AC-FRM-05).
- Закупівлю в чужий відділ чи недозволеного типу, подану напряму, оминаючи сторінки, не подано (AC-FRM-02, AC-FRM-04).
- Без жодного рядка закупівлю не подано й показано «Додайте хоча б один рядок»; з рядком — статус «Очікує схвалення»,
  зокрема у відділі без схвалювача й коли єдиний схвалювач — сам автор (AC-FRM-06, AC-FRM-07, AC-FRM-12, AC-FRM-13).
- Чужу закупівлю за прямим посиланням не показано — «Недостатньо прав»; гість бачить сторінку входу (AC-FRM-08,
  AC-FRM-09).
- Сторінка «Мої заявки»: власні заявки зі статусами, «Закупівлю подано» після подання, порожній стан «Ви ще не подали
  жодної заявки» (AC-FRM-10, AC-FRM-11, AC-FRM-14).

Рішення схвалювача (`approval-decision`):

- Список для рішення схвалювача — лише заявки його відділу зі статусом «Очікує схвалення» (AC-APR-01).
- Схвалення — статус «Схвалено»; відхилення з причиною — «Відхилено», причину збережено; без причини — «Вкажіть
  причину», статус не змінюється (AC-APR-02, AC-APR-06, AC-APR-07).
- Чужий відділ, заявник без права рішення, власна заявка схвалювача — відмова, статус не змінюється (AC-APR-03,
  AC-APR-04, AC-APR-05).

Англійський інтерфейс (`ui-language`):

- Усі написи інтерфейсу на всіх сторінках, зокрема сторінках першого зрізу, — англійською за таблицею з
  `requirements/49-…md`; сторінка входу й помилка входу — англійською (AC-LANG-01, AC-LANG-02).
- Повідомлення «Not enough permissions», «Add at least one line», «Provide a reason»; статуси «Awaiting approval»,
  «Approved», «Rejected» — текстом (AC-LANG-03, AC-LANG-04, AC-LANG-05, AC-LANG-06).
- Історія й автосхвалення англійською, введені людьми дані — без перекладу; ідентифікатори ролей і номери заявок — без
  змін, підпис ролі — англійською (AC-LANG-07, AC-LANG-08).

Деактивація працівника (`employee-deactivation`, уточнення першого зрізу):

- MODIFIED AC-ORG-12: деактивований працівник не входить у систему й бачить повідомлення «Обліковий запис деактивовано.
  Зверніться до адміністратора» (ValiaBihun/2026-quitcode-dream-team#45).
- REMOVED AC-ORG-13 (видалення чернетки деактивованого працівника): заявок і чернеток у першому зрізі немає, критерій
  перенесено в WS7-чернетку — рішення PM ValiaBihun/2026-quitcode-dream-team#43.

## Capabilities

### New Capabilities

- `purchase-form`: форма закупівлі з відділами й типами за правами працівника, подання, відмови без змін у даних,
  сторінка «Мої заявки».
- `approval-decision`: список для рішення схвалювача свого відділу, схвалення, відхилення з причиною, відмови.
- `ui-language`: усі написи інтерфейсу англійською за таблицею PM, без перекладу даних, які ввели люди.

### Modified Capabilities

- `employee-deactivation`: вимогу «Деактивація працівника» прибрано (REMOVED, рішення PM ValiaBihun/2026-quitcode-dream-team#43, ValiaBihun/2026-quitcode-dream-team#45) і замінено вимогою «Вхід і вибір деактивованого працівника» — AC-ORG-12 з повідомленням при вході, AC-ORG-16, AC-ORG-28; без AC-ORG-13.

## Users & roles

| Роль | Сутність | Дія в цьому зрізі |
|---|---|---|
| гість | Форма, заявки, список для рішення | доступу немає — лише сторінка входу (AC-FRM-09) |
| `requester`, `approver` | Закупівля | подає лише у відділ, де він заявник, лише дозволеного типу (C); бачить лише власні (R) |
| `approver` | Подані заявки свого відділу, крім власних | бачить у списку для рішення (R), схвалює й відхиляє з причиною (U) |
| `requester` | Список для рішення | доступу немає (AC-APR-04) |
| `admin` | Закупівля | подає в будь-який відділ, будь-якого типу (AC-ORG-22, AC-ORG-23, AC-ORG-29) |
| `admin` | Список для рішення, рішення | у цьому зрізі окремих критеріїв немає — наступний зріз (примітка під матрицею прав) |

Матриця прав `requirements/product.md`: «Подавати закупівлю — лише у відділ, де він заявник» (`requester`, `approver`),
«у будь-який відділ» (`admin`); «Бачити список для рішення — лише подані заявки свого відділу, крім власних»
(`approver`); «Схвалити… відхилити — заявки свого відділу, крім власних» (`approver`); не увійшов — лише сторінка входу.

## Non-goals

- Рядки закупівлі: суми, обчислення, ліміти й перевірки кількості та ціни; номер заявки й історія подання — наступний
  зріз (ValiaBihun/2026-quitcode-dream-team#47 «Поза межами»).
- Часткове схвалення, відхилення окремого рядка, повернення на доопрацювання; рішення адміністратора за відділ без
  схвалювача; кілька схвалювачів по черзі; ліміти сум (ValiaBihun/2026-quitcode-dream-team#48 «Поза межами»).
- Інші типи заявок («Відшкодування», «Витрата карткою», «Запит на чек», «Рахунок постачальника») — WS9–WS11.
- Подання від імені колеги й автосхвалення в заявках — додаткові функції, не входять до спрощеного скоупу
  (ValiaBihun/2026-quitcode-dream-team#46).
- Перемикач мов, переклад даних, які ввели люди, зміна форматів дат і сум (ValiaBihun/2026-quitcode-dream-team#49 «Поза межами»).

## Assumptions

PM:

- Відділи, заявників і дозволи вже налаштовано в першому зрізі; користувачів і ролі створює адміністратор, без листів.
- Відмова для чужої заявки й чужого відділу однакова — «Недостатньо прав», вона не розкриває вміст заявки; відмова
  прямого запиту (власна заявка схвалювача) тексту на екрані не має.
- Адміністратор бачить усі відділи й типи закупівлі (AC-ORG-22, AC-ORG-23, AC-ORG-29).
- Ціна рядка — число з двома знаками після коми.
- Чернетка до подання — додаткова функція: «закупівлю не подано» означає, що в списку немає нової заявки зі статусом
  «Очікує схвалення» (ValiaBihun/2026-quitcode-dream-team#50).
- Відділ без активного схвалювача не блокує подання; якщо єдиний схвалювач — автор, заявка чекає іншого схвалювача або
  рішення адміністратора в наступному зрізі (ValiaBihun/2026-quitcode-dream-team#52).
- Рішення приймає будь-який один схвалювач відділу.
- Англійська одна для всіх; таблиця з `requirements/49-…md` — чинні тексти: якщо чинний AC цитує український текст,
  діє англійський з таблиці, ID не змінюються; один термін — один переклад.
- Дати й час — за часом `America/New_York`.
