# 0006. Журнал AI-помічника: рядок ai_calls на кожен запит «Suggest lines» (замінює частину 0004)

- Статус: прийнято
- Дата: 2026-11-21
- Замінює: [0004](0004-ai-feature-openrouter.md), пункт «Людина в контурі» — лише слова «Server Action пропозиції
  нічого не пише в базу». Решта 0004 чинна.
- AC: — (нових AC немає; AC-AI-01, AC-AI-05, AC-AI-06 лишаються: заявку створює лише людина)

## Контекст

WS11 (трек B, промпт R07) вимагає журнал AI-функції `llm.call`, а PM у ValiaBihun/2026-quitcode-dream-team#83 визначила
SLO-2: частка запитів «Suggest lines» за добу, після яких людина бачить пропозицію, а не «The assistant is unavailable
today» (AC-AI-05) чи «Could not get a suggestion…» (AC-AI-04), за 28 днів; джерело — «журнал AI-функції зі станом
кожної відповіді». Журнали Vercel Hobby живуть 1 годину, тож лише рядка `llm.call` у Runtime Logs замало: дані за 28 днів
мають лежати там, де вони зберігаються. 0004 казала, що дія пропозиції нічого не пише в базу — так задумано, щоб модель
не могла нічого створити без людини.

## Рішення

Дія `requestLineSuggestion` після перевірки прав пише **один рядок журналу** в `public.ai_calls` (міграція
`20261121194502_ai_calls.sql`) і один рядок `llm.call` у журнал — для кожного запиту, зокрема відмови до виклику моделі.

- Рядок — лише факти без тексту: стан (`ok / needs_info / refused / unavailable`), стан застосунку, код причини,
  модель, затримка, токени, версія промпту, id запиту, `user_id` (= `auth.uid()`). Опису, промпту й відповіді моделі
  немає (тести з маркером `MARKER-7f3a`).
- Заявок, рядків закупівлі й будь-чого, що бачить чи змінює бізнес-процес, дія як і раніше **не пише**: людина в контурі
  незмінна — запис закупівлі лише через `submitPurchase` після дії людини (AC-AI-01, AC-AI-06).
- Запис іде **після відповіді** людині (`after()` з `next/server`): журнал не додає затримки до 15 с AC-AI-04, а збій
  вставки не змінює відповідь (лише подія `ai_calls.insert_failed` з кодом).
- Доступ: читає лише активний адміністратор; пише користувач лише свій рядок (RLS, `grant insert` без `user_id`,
  `created_at`, `id`); без update/delete; 35 днів зберігання (тригер).
- SLO-2 рахує запити, де людина отримала збій сервісу: `app_state in ('failed','unavailable')`, **крім** помилок вводу
  без виклику моделі (`model_called = false and error_kind in ('empty_input','too_long')`) — як у практиці SLO (лише
  коректні запити); PM повідомлено.

## Розглянуті варіанти

- Лише `llm.call` у Runtime Logs — ні: 1 година на Hobby, SLO за 28 днів не виміряти.
- Log Drains Vercel у зовнішнє сховище — ні: лише тариф Pro.
- Запис через секретний ключ (admin-клієнт) — ні: `SUPABASE_SECRET_KEY` у Vercel заборонено (`AGENTS.md`).
- Без `user_id` — ні: будь-хто з входом міг би вставити рядки, що спотворюють SLO; з `user_id` RLS пускає лише свій
  рядок (рішення розробника 21.11).
